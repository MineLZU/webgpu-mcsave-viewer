# 状态如何转成正确的网格

输入为已验证的展示协议消息，输出为 `wgpu-mc` Section 烘焙任务；状态与 GPU 网格分别管理版本。

## 状态及失效规则

| 环节 | 规则 |
|---|---|
| 状态映射 | 用字典中的完整名称/属性匹配资源模型，构建状态 ID → `BlockstateKey`；不能把两类 ID 直接互换 |
| 状态缓存 | 以世界会话、维度、Section 坐标为键，保存方块、biome、光照、revision、数据有效性及脏标记 |
| 即时应用 | 消息先更新状态、合并同段脏标记；可见性只控制重建优先级，不能阻止状态接收 |
| 邻域失效 | 首期保守标脏目标及 26 个相邻 Section，覆盖边、角、AO、流体和光照采样；更大采样半径须同步扩展依赖 |
| 无效推断 | 单一“不透明”布尔值不足以证明相邻网格不变；精确减少标脏范围必须以渲染依赖与回归样本为依据 |
| Halo | 烘焙使用一致的 3×3×3 Section 快照，记录全部依赖版本；未知、已知空气和世界外边界分别表达 |
| 缺少邻居 | 未知邻居按非遮挡处理并标记结果为临时；后续到达触发重建，不能无限等待未加载区块 |
| 结果提交 | 仅提交自身及邻域版本、资源代次仍匹配的结果；丢弃过期结果并保留重建需求 |

## 调度与可见性

| 环节 | 规则与现有入口 |
|---|---|
| 渲染数据供给 | 实现 `BlockStateProvider` 的状态、流体、光照、着色和模型变体输入：`wgpu-mc/src/mc/chunk.rs:74` |
| 洞穴可见性 | 使用现有 6×6 位关系：`wgpu-mc/src/render/section_graph.rs:126`；浏览器补齐数据来源，不另建 15-bit 格式 |
| 连通性失效 | 状态变化独立失效连通性；未知/过期关系保守可见，避免旧剔除结果阻止新网格产生 |
| 工作预算 | 视锥内、近处优先，保留公平性；单线程任务可分段让出事件循环，不以固定每帧 8～16 个保证帧率 |
| 烘焙与上传 | 复用 `wgpu-mc/src/mc/chunk.rs:1395` 的烘焙能力，拆分纯 CPU 计算与 GPU 提交边界 |
| 缓存预算 | 状态、待烘焙任务、CPU 网格、GPU 区间分别限额；世界切换清理状态与现有全局可见性缓存 |

验收覆盖石头换矿石、玻璃/树叶、边角 AO、独立光照、流水、邻居晚到、开洞后的可见性恢复和过期任务提交；透明几何随摄像机移动的排序见 [WebGPU 适配](viewer-webgpu.md)。

## 已知偏差

现有可见性缓存依赖外部写入，说明见 `wgpu-mc/src/mc/visibility.rs:1`；抽取出的引擎没有网页状态管理器。单线程预算需要可让出的烘焙入口，仅限制任务数量仍可能长时间阻塞主线程。
