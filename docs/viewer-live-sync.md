# 热更新如何可靠到达浏览器

以下为待实现契约。Java 21 模组主动连接 Native 网关的独立入口，网关对浏览器提供 HTTP 和 WebSocket；首期使用未压缩的应用层二进制消息，不复用游戏端口或原版包 ID。

## 捕获与网关职责

| 环节 | 规则 |
|---|---|
| 权威捕获 | 在实际状态修改路径按 Section 去重，Tick 边界读取最终值；加载时采集完整快照，独立记录光照更新和卸载事件 |
| 无人监听区块 | 不以 `ChunkHolder#broadcastChanges` 是否执行作为唯一依据；P0 对照 1.21.11 映射核实修改与生命周期入口 |
| 线程边界 | 游戏线程生成一致的不可变批次；网络、压缩及文件读取不在游戏线程执行，不把活的 Chunk 引用交给发送线程 |
| 订阅 | 浏览器订阅维度与视域；网关合并请求，模组只读取已加载目标，不增加强制加载 ticket；订阅外缓存受预算约束 |
| 部署 | 默认本机连接；对外通过 HTTPS/WSS 提供安全上下文，桥接入口与浏览器入口分离，桥接凭据及浏览器访问凭据由应用配置 |
| 静态资产 | 字典和资产以游戏版本、内容哈希寻址；握手引用资源，重连不重复推送完整字典 |

## 展示协议的最小接口

接口名称描述职责，不表示 fork 已有 API；字节布局、长度限制和跨语言样本在 P0 一同定版。

| 消息 | 必须表达的信息 |
|---|---|
| 初始化 | 展示协议版本、世界会话、游戏版本、字典/资产哈希、维度标识与高度 |
| 订阅／取消 | 维度、目标范围、订阅代次；迟到响应不得恢复已取消订阅 |
| Section 快照 | 显式坐标、revision、4096 方块、64 biome 样本、天空光/方块光及其有效性；空段必须能清除旧内容 |
| 方块增量 | Section、`baseRevision`、新 revision、局部位置和状态 ID；单点和多点共用语义，不固定原稿的 512 阈值 |
| 光照更新 | 独立的天空光/方块光数据、有效性和版本；不要求同时存在方块变化 |
| 生命周期 | 区块变为热态、卸载、不可用、世界/维度切换与会话重置；卸载不等于全空气 |
| 重新同步 | 订阅或 Section 的快照请求；用于断线、积压丢弃、版本断层和状态基准失效 |

## 一致性与背压

| 情况 | 处理 |
|---|---|
| 快照期间修改 | 同一权威版本点截取快照，随后发送基于该 revision 的增量；不能把异步读取的混合状态标成一致快照 |
| 版本断层 | 以会话、维度、Section 坐标定位状态；仅应用匹配基准的增量，失配请求快照，重复/旧消息不回滚状态 |
| 连接重建 | 重新确认会话、字典和订阅，以快照重建基准；旧画面可保留为过期状态，不能继续接未知基准增量 |
| 模组发送队列满 | 有界队列不阻塞 Tick；丢弃后在有界订阅状态中标记需重建，恢复时发送新快照，不能静默丢增量 |
| 浏览器落后 | 每连接有界排队并隔离慢消费者；不能保持版本连续时断开并重新同步，不拖慢其他浏览器 |
| 字典/资源变化 | 校验哈希后建立新映射，统一失效相关状态与网格；未知 ID 或缺失模型有明确诊断/占位 |

跨语言验收以 JVM、Kotlin/Native、Rust 共用固定样本为准，覆盖负坐标、不同高度、空段、截断消息、非法长度、越界状态 ID 和不匹配 revision。

联调覆盖无人监听、同 Tick 多次修改、加载/卸载、独立光照变化、快照竞争、取消订阅、重连和慢消费者。记录捕获开销、积压和呈现延迟；Tick 捕获目标不作为端到端延迟保证。
