# Minecraft 1.21.11 网页世界展示器架构方案

文档版本：**v2.1**。目标是浏览器展示运行中服务端的原版地形，并在存档刷盘前反映修改。

## 已确定的边界

| 项目 | 决定 |
|---|---|
| 游戏与桥接 | Minecraft Java Edition **1.21.11 / Java 21**；Fabric 先落地，NeoForge 后续接入 |
| 网关 | **Kotlin/Native 独立进程**，采用 Ktor CIO；首个验收目标为 Windows x64，后续验证 Linux x64 |
| 浏览器 | TypeScript 宿主 + Rust/WASM + `wgpu-mc` WebGPU；首期 Chromium、单线程 WASM |
| 首期内容 | 已加载区块的普通方块模型、流体、光照、生物群系着色及实时更新 |
| 版本适配 | 只适配展示器需要的数据子集；不要求完整原版登录、会话和网络协议降级 |
| 资源与缓存 | 使用明确匹配 1.21.11 的资产；字典、资源按版本与内容哈希缓存 |
| 通信 | 模组主动连接独立网关；两段链路均使用 WebSocket，浏览器资源使用 HTTP |
| 后续能力 | 冷区块、NeoForge、Linux 部署及测量驱动的性能优化 |

## 当前基础与目标拓扑

现有 Rust workspace 只有渲染器及其辅助 crate；`minecraft-protocol/` 是独立 KMP checkout，尚未集成。源码入口见[工程分层](architecture.md)，fork 的版本差异见[fork 集成边界](viewer-fork-integration.md)。

**Fabric 捕获模组 → Kotlin/Native 网关 → 浏览器状态缓存 → `wgpu-mc` WebGPU**。

模组负责权威快照和增量；网关负责状态汇聚、订阅与资源；浏览器即时应用状态，按可见性和预算重建网格。冷区块在后续阶段由网关只读访问存档，再投影到同一展示数据模型。

## 实施顺序与退出条件

| 阶段 | 退出条件 |
|---|---|
| P0：技术验证 | Native HTTP/WebSocket 收发、浏览器最小地形绘制、1.21.11 资源与注册表导出均成立；展示协议布局与跨语言样本共同定版 |
| P1：热更新闭环 | Fabric 初始快照、方块变化及独立光照更新贯通浏览器；无需等待 `.mca` 刷盘 |
| P2：稳定运行 | 订阅切换、断线恢复、快照竞争、慢消费者、资源缺失及内存预算均有明确处理 |
| P3：冷区块 | 真实 1.21.11 存档可读，并发写盘失败可恢复；磁盘旧数据不能覆盖热状态，不触发游戏加载或生成 |
| P4：平台与优化 | NeoForge 复用同一契约；Linux Native 部署验证；根据测量决定压缩、Worker、GPU 剔除和间接绘制 |

验收场景分别见[捕获与同步](viewer-live-sync.md)、[状态调度](viewer-state-scheduling.md)、[WebGPU 适配](viewer-webgpu.md)和[冷区块](viewer-cold-chunks.md)；实际执行记录只写入[验证记录](build.md)。

## 已知偏差与非目标

| 边界 | 原因与处理 |
|---|---|
| 游戏版本与依赖版本不同 | fork 当前选择 26.3；1.21.11 兼容性必须由适配层和真实样本证明 |
| 完整原版画面尚非承诺 | 实体、方块实体专用渲染和任意模组客户端逻辑不在首期；缺失内容显示占位或明确说明 |
| 性能指标尚无依据 | Tick 边界捕获不等于端到端 50ms；记录捕获开销、积压、呈现延迟、烘焙和内存后再定预算 |
| 高级传输不进入基础链路 | 同游戏端口嗅探、共享内存、FFM、WebTransport、应用层 LZ4 均不作为首期前提 |
