# 冷区块如何与热状态共存

冷读属于 P3，由 Native 网关访问明确配置的世界目录；首期热更新不等待这条链路。

## 数据来源与优先级

| 环节 | 规则 |
|---|---|
| 文件访问 | 复用 `LiveMinecraftWorldAccess`，入口为 `minecraft-protocol/world-io/src/commonMain/kotlin/com/hiczp/minecraft/world/io/LiveMinecraftWorldAccess.kt:29`；不获取 `session.lock`，不修复或写回存档 |
| 版本投影 | 从底层 NBT 读取 1.21.11 所需字段；显式提供维度、字典和默认状态，方块状态用 `BlockStateNbtLayout.NAME_PROPERTIES` 解码，不能直接套用 26.x 高层默认解码 |
| Section 数据 | 保留有符号 Y、方块/biome 调色板、光照和缺失语义；NBT 位数组与原版网络容器分开处理 |
| 热态优先 | 已收到本会话热状态的区块由热流控制；异步磁盘结果必须检查请求时的热态代次，发生变化即丢弃 |
| 卸载衔接 | 模组在卸载前提供最终快照；网关保留最后热快照，直到磁盘投影与其渲染数据匹配后才交回冷读，不能只比较时间戳 |
| 有界保留 | 预算不足可逐出未订阅状态；无法证明磁盘追上热状态时，标为不可用并等待可靠数据，不静默显示回滚状态 |
| 不触发游戏加载 | 缺少区块或文件时返回未知/不可用，不调用加载或生成 API，也不把缺失伪装成全空气 |

## 并发读与故障边界

| 情况 | 处理 |
|---|---|
| 正在写盘 | live handle 不保证快照一致性：`minecraft-protocol/world-io/README.md:434`；对 I/O、压缩和 NBT 失败进行有限重试，保留旧画面并标记过期 |
| 文件替换 | 重试时重新打开句柄；处理 `.mca` 与外置 `.mcc`，结束所有读操作后再关闭句柄 |
| 数据不完整 | 检查坐标、维度高度及生成状态；未完成生成或不支持的版本只报告缺失/不支持 |
| 格式不兼容 | 读取兼容不等于完整世界升级；不修改 `DataVersion`，不承诺实体、数据包或其他版本自动迁移 |

验收使用真实 1.21.11 样本，覆盖负坐标、单值/多值调色板、非跨 Long 位打包、空段、不同维度、文件替换、写盘失败及冷读与热更新竞争。

## 已知偏差

fork 当前高层解码以其选定版本为准；即使容器读取成功，也必须完成 1.21.11 地形投影验证。live 读取只能提供可失败的观察，不能宣称跨进程一致快照。
